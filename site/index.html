homeskillet
Install Use Repository Safety Docs

Easily manage your dotfiles across Linux, macOS, and Windows.

homeskillet links the dotfiles from your own repository into your home directory, on every machine you use, and bootstraps your system tools too: the manifest can install your shell prompt, language toolchains, editors, and packages, each step shown to you and run only once you approve it. One small, dependency-free binary, with nothing to configure but your repository.

Install Latest release

Built for safety first

Linked files such as .bashrc run as you, so homeskillet treats a repository the way OpenSSH treats ~/.ssh.

Never overwrites your files

It refuses to replace or delete anything it did not create. Conflicts are reported; --force moves each one into a backup it never deletes.

Checks ownership and permissions

A repository, file, or symlink that another user could change is refused, and running as root needs --allow-root.

Shows every step before it runs

Setup steps are someone's code. Each is shown exactly as it will run, with no shell, expansion, or templating, and "no" is the default.

Dry runs everywhere

Every command that writes into a home directory takes --dry-run and changes nothing.

Install

Pick your system for its install commands. Each downloads the latest release, checks it against the release's SHA256SUMS, runs it only if it matches, and lets it install itself as a versioned command under .local in your home.

  • Linux x64 or Arm, including WSL distributions and containers
  • macOS Apple silicon or Intel
  • Windows in PowerShell, step by step: picks the build for your PC, and its prepare turns on Developer Mode and offers Git, each only once you approve

From then on, homeskillet manages its own versions. Each version keeps its own copy, so going back is one command:

homeskillet update            # install the newest release and run it, keeping the one you have
homeskillet list              # installed versions, and which one runs
homeskillet list-remote       # published versions, and which are installed
homeskillet install 0.3.1     # install that release, without changing which one runs
homeskillet use 0.3.1         # run that version; use latest follows the newest again
homeskillet remove 0.3.0      # delete a version you no longer need, unless it runs

update checks each download against the release's SHA256SUMS before anything runs.

From source, with Go

For developing homeskillet, or bringing it to another system: with Go 1.24 or newer, make install builds a clone and installs it as a version of its own (building from source). The build uses the standard library only, so there is nothing else to fetch.

Use

Point homeskillet at a repository. Without a command it reports what link would change.

homeskillet ~/dotfiles                        # status: what link would change
homeskillet link ~/dotfiles --dry-run         # preview; nothing changes
homeskillet link ~/dotfiles                   # link every file
homeskillet link ~/dotfiles .bashrc --force   # replace ~/.bashrc, keeping a backup
homeskillet setup ~/dotfiles                  # offer each setup step
homeskillet check ~/dotfiles                  # list every issue, or say it is valid
homeskillet backups purge --older-than 30d    # delete old backups, after asking
homeskillet unlink ~/dotfiles
homeskillet prepare                           # check for Git and, on Windows, Developer Mode
homeskillet update                            # install the newest release and run it

After the first link, the repository may be left out anywhere. At a terminal the output is grouped for reading; in a script it is one tab-separated line per file, and the exit status reports the result. A failure is one line and a hint; --verbose shows all of it.

Configuring a repository

The simplest repository is a home/ directory laid out as your home. Every file under it is linked to the same path in yours.

dotfiles/
└── home/
    ├── .bashrc                -> ~/.bashrc
    └── .config/git/config     -> ~/.config/git/config

An optional manifest at the root, bootstrap.json or dotfiles.json, adds what home/ cannot say: the platforms the repository is for and the setup steps that install tools. homeskillet init writes a starter.

{
  "platforms": ["darwin"],
  "setup": [
    { "name": "homebrew", "run": ["bash", "setup/homebrew.sh"], "provides": "brew" }
  ]
}

To start from a working one, copy the example for Linux, macOS, or Windows. The manifest guide describes every field.

Safety

homeskillet never overwrites or deletes a file it did not create, short of backups you ask it to purge after it lists them, and refuses to run as root, or elevated on Windows, without --allow-root. Linked files and setup steps run as you, so it refuses a repository, source, or symlink another user could change, and shows each setup step exactly before you approve it.

Review someone else's dotfiles before linking them, and especially before setup --yes. The safety guide lists every refusal and the reasoning behind it, and SECURITY.md says how to report a vulnerability.
